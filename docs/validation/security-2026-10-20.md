# Security review, 2026-10-20

This review follows GHSA-x294-8g9c-m6fc and covers the application trust
boundaries described in [security verification](../security.md). Development
is public on main as requested. Only isolated fixture accounts, containers
and extracted native archives are used; no production installation is tested.

## Findings and changes

| Finding | Evidence and disposition |
| --- | --- |
| GHSA-x294-8g9c-m6fc: settings-selected Sendmail executable | Confirmed data flow into CodeIgniter 4.7.5's command string. Removed all web/state authority over executable selection; operator-only immutable path, complete symlink/directory checks and shell quoting. Old custom paths require explicit operator migration. |
| Mail fingerprint interpreted differently from delivery | Confirmed equal fingerprints for `tls` and `TLS` while the library used different encryption branches. Settings, delivery and verification now share canonical effective transport configuration and a new verification contract. |
| Unpersisted mail probes can use saved secrets with overridden targets | Request merging was confirmed. Probes now use saved configuration only, require reauthentication, share an account rate limit and reject overrides before initialization or connection. No real credentials were transmitted during analysis. |
| Delegated user administration can exceed its authority | Confirmed account creation/reset and role/group assignment paths without delegation limits. Actor-aware mutations check persisted rights and affected accounts under the state lock, including indirect group/role effects, home scope and extension policies. File and SQLite denial/rollback and controller regressions cover these paths. |
| FTPS certificate preflight authenticates a different connection | Confirmed from adapter flow and PHP's documented lack of peer verification in `ftp_ssl_connect`. Strict mode now refuses legacy FTPS even with a `tls_verified` claim. Explicit operator compatibility mode retains the legacy transport with a warning; verified same-connection FTPS needs a separate transport migration (Beads ex3-45y.7). |
| FTP PASV can select an unapproved data address | Forced `FTP_USEPASVADDRESS=false`. The real remote fixture advertises a hostile loopback PASV address while file operations must still use its authorized control peer. |

The original upload/chmod behavior remains available as file management;
application data cannot become the mail executable. SMTP and PHP mail remain
supported. The complete administrator retains authority; delegated roles do
not gain settings permission automatically.

## Reviewed boundaries

| Surface | Review and behavioral evidence |
| --- | --- |
| Execution and configuration | Application process/eval/deserialization search, all EmailService call sites including CLI reminders, shell-safe operator path fixture and extensionless upload/chmod/browser regression. PHP state is decoded as protected JSON, not included as executable PHP. |
| Authentication and authorization | Login, installation claim, profile/2FA, remember-me, WebDAV credentials, current-session authorization versions, administration CRUD, mounts and API permission checks. Existing security suites plus new delegation regressions cover denial and persisted-state rollback. |
| Storage and upload lifecycle | VFS path/namespace policies, local and remote adapters, archive extraction, version/trash restoration, resumable sessions, frozen upload targets and quarantine promotion. Existing traversal, symlink, resource, revocation and concurrency regressions are retained. |
| Public capabilities | Share creation/projection, owner authorization, password-session binding, expiry, revocation, upload-only restrictions, filename policy and share-upload locking. Home scopes and intentionally shared storage are distinguished. |
| Browser and resources | Escaping of filenames/messages/log fields, static compiled Vue templates, safe inline-download type allowlist, image/archive/staging limits, CSP and CSRF refresh/error handling. |
| Deployment and dependencies | Read-only code volume, non-root worker, operator environment, metadata separation, native routing/packaging and dependency/browser-asset/container gates. |

This is a source review and regression campaign, not ASVS certification or a
claim that all possible vulnerabilities have been eliminated. Hostile local
OS processes and fully adversarial race/fuzz testing need separate isolation
and testing work. The targeted Semgrep rules prevent known execution patterns;
they do not provide cross-file taint analysis. Further verification is tracked
in Beads rather than duplicated as a Markdown task list.

## Prepared advisory information

The Sendmail data flow was introduced in commit `c8047ec` and is present in
tags `v3.0.0-beta.6`, `v3.0.0`, `v3.1.0` and `v3.1.1`. This is historical
source verification; the local runtime reproduction targeted current 3.1.1
code. The corrected version is 3.1.2. The report is attributed to `dutchypoo`;
its reported CVSS 9.1 assessment is retained as the reporter's assessment,
not represented as an independently recomputed score.

The essential cause is application control over the executable, in addition
to unsafe command construction. Merely quoting the uploaded program, denying
one extension or requiring another password would not fix that boundary.
The fix retains Sendmail through immutable operator configuration and rejects
web changes and legacy-program execution across every mail entry point.

Upgrade notes must explain custom-path migration, renewed mail verification,
explicit settings permission, bounded administration and the strict FTPS
restriction. Install the security patch; changing the selected mail transport
alone does not remove the vulnerable program-selection capability from an
older installation. If there is evidence of prior code execution, investigate
the host and rotate affected secrets rather than treating a code update as
remediation of an already compromised system. This review found no evidence
of production exploitation and performed no production investigation.
