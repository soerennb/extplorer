## Publication contract

Archive and container success are both required before public release or moving
aliases. The final job verifies ZIP/checksum bytes, stages immutable assets in a
draft, moves `3.1`, `3` and `latest` to the verified version manifest and publishes
the GitHub release. Previous alias digests are recorded and restored on failure.
Retries reuse successful artifacts; different version manifests/assets fail.
The packaged translation and actual final ZIP routing/upgrade gates always run,
including when same-SHA checkout CI gates are reused.

See [release procedure](../dependency-updates.md#coordinated-publication) and
[cross-version check commands](../../tests/e2e/README.md#cross-version-release-upgrade).
